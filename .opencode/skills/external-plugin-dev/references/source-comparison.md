# 从参考实现提取可落地能力

适用于 Pi、OpenCode 2.0、Codex 或用户给出的其他源码。名称不能确定仓库身份；检查路径、remote、branch、commit 和 dirty 状态。缺少目录或空目录就记为未提供，不猜 API，不自动替用户 clone 指定以外的仓库。

针对当前需求定向查找入口、配置、类型、调用链、测试和失败处理；不要先全文总结所有参考库，也不运行参考库的安装脚本。记录：

| 字段 | 要求 |
| --- | --- |
| 来源 | 仓库路径、remote、commit、文件和符号；dirty 内容注明未提交 |
| 已证实机制 | 从入口到行为的调用链及相关测试，不把注释等同实现 |
| 本项目需求 | 具体解决哪个问题；不相关能力留在范围外 |
| 固定内核映射 | 可用的公开 Hook/SDK 与精确源码位置，或明确缺口 |
| 最小实现 | 本地变更位置、数据/生命周期边界、兼容策略 |
| 验证 | 正常行为与相关失败路径，哪些尚未执行 |
| 复用条件 | 若复制代码，先确认许可证和署名要求；不确定就记录 |

在已有 design 中保留这一映射。区分“已读源码”“来自用户摘录”“推断”“尚待验证”。参考实现只提供技术证据，不提供执行权限、监控授权或内核升级许可。
