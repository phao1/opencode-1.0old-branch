- **P1：恢复控制消息被拒绝后，异步错误可能影响新的正常会话。** 设计要求失效的 synthetic control 在 `chat.message` 中抛错，同时要求该错误不能清理新一轮状态，但没有规定如何关联和识别随后到达的错误事件（[DESIGN.md:50](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L50)、[DESIGN.md:51](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L51)）。固定内核的 `prompt_async` 会把该异常另行发布为 `session.error`（[session.ts:851](agent-kernel/packages/opencode/src/server/routes/session.ts#L851)）；若真实用户已开始新一轮，按设计的通用错误处理会清掉新状态，还可能向用户显示错误。建议明确为每次被拒绝的自家 control 关联唯一标识，并仅忽略可确认属于该 control 的后续错误；加入“拒绝旧 control → 新请求开始 → 旧错误迟到”的回归。备选是不抛错，但必须先证明不会保存并执行失效 control，否则会扩大取消竞态。

- **P1：请求归属证明缺少其他插件修改消息的边界。** 内核按加载顺序依次调用共享 `messages` 输出上的 transform hook（[plugin/index.ts:243](agent-kernel/packages/opencode/src/plugin/index.ts#L243)）。因此，本插件看到 transform 后的输入并不能单独证明最终模型请求不包含它：后续插件可能在同一次 transform 中加入该消息；反过来，也可能移除本插件认定已吸收的消息。设计目前把最近 transform 与最终请求等同（[DESIGN.md:13](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L13)、[DESIGN.md:46](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L46)）。建议明确验证并约束插件顺序及并存假设；若公开接口无法确认最终消息集合，则将此情形标为无法保证，并对可检测的不确定情况放行。增加前后置 companion plugin 修改 messages 的测试，避免把串行 loop 证明扩大为最终请求内容证明。

- **P2：idle 事件与 status 读取存在时序窗口，G2 可能无故放弃。** 内核先发布 `session.status: idle` 和 `session.idle`，然后才从 status map 删除忙碌状态（[status.ts:73](agent-kernel/packages/opencode/src/session/status.ts#L73)）。设计在收到 idle 后调度恢复，并要求查询 status 确认 idle（[DESIGN.md:50](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L50)、[DESIGN.md:51](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L51)）；若查询赶在删除之前，可能读到旧 busy，且一次性候选不再重试。建议明确在事件发布完成后的异步调度点再执行检查，并用固定内核测试该顺序；若仍不能可靠判断，则保留 fail-open 放弃恢复的限制并如实记录。

- **P2：摘要 transform 无法识别会话时，压缩标记的清理规则不明确。** 设计通过消息集合唯一推断 sessionID，歧义时不关联（[DESIGN.md:46](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L46)）；压缩 hook 则按 sessionID 标记“下一次 transform 是摘要”（[DESIGN.md:49](docs/oneshot/runs/20261104-0553-steering-v21/DESIGN.md#L49)）。若摘要消息为空、跨会话或被其他插件改变，摘要 transform 无法消费标记，后续普通请求可能被误判为摘要，漏掉 G1/G3。建议规定歧义时如何失效相关标记，无法安全关联时宁可放弃该压缩周期的优化，并覆盖空消息和跨会话消息的回归。
